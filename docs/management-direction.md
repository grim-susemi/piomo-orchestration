## D1. Preserve one private source history

Keep grim-susemi/piomo-orchestration, private and independent, with main as the
publication target. Preserve both historical commits and their coverage gaps.
Add current records without amending or relabeling historical deployment.

## D2. Separate layers and identities

Curated Git source, deployed user custom files, lane launcher/re-entry,
upstream runtime and local evidence are different layers. Record original,
Git-normalized publication and deployed identities separately. Unknown source
revisions remain null. Every publication adaptation needs its operation,
reason and bounded behavior difference. Raw homes, models, credentials,
generated bundles, logs and backups are excluded. Missing source is a named
gap, never replaced by generated output.

## D3. Reuse native parallel operation

Senpi already carries native independent-call batching. Use existing eval
and parallel for independent reads/searches/listings/diagnostics; preserve and
inspect every result, including failures or truncation. Input-dependent calls
and side effects remain sequential, one writer per file and tree. Sizeable
independent work may use workers under its applicable task policy. Do not add
another engine, role, interceptor, duplicate native paragraph or performance
claim. In particular, do not add Sol 6.1 to the legacy tuning allowlist: the
current exact matcher excludes it, so unrelated legacy directives stay off.

## D4. Accept preservation during a requested update

Use the existing stable-500 update process, not a new updater or watcher.
Record old pins and custom identities; stage the requested version and assess
compatibility; re-pin launcher/re-entry under installation scope; check home
bytes and intended home/plugin selection without reviving parked plugins;
verify loading/model applicability and two independent read-only calls after
restart; confirm native parallel capability survives; record the updated
state and bounded results. Package-independent storage alone proves neither
loading nor behavior. Task11 records these acceptance steps separately;
no update or restart is performed here.

## D5. Keep evidence labels distinct

Direction finalized means a recorded decision. Source prepared means actual
source exists. Self-verified means relevant checks passed on that source.
Applied means exact bytes were deployed. Runtime verified means intended
loading and behavior were observed. Pushed means the approved remote ref
matches. No label implies the next, and no installed file proves model match.
The native agentDir AGENTS.md candidate is a separate future activation target,
not permission to write a home-level context shortcut.

## D6. Preserve the current baseline first

Curate and verify the current stable-500 source and safe provenance before
optional optimization records. Commit only under explicit current Git scope;
publish only after review and exact private-write approval, then read back
the remote ref. Worker-guidance repair remains a separate candidate and must
not be called applied or model-verified from source preparation. A specific
reproducible upstream defect, not existing native capability, would justify
considering an upstream change.
